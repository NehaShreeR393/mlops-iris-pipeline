# MLOps Pipeline — Iris Classifier with MLflow Tracking + Flask Serving API

An end-to-end MLOps mini-pipeline: trains a classifier, tracks the experiment with
MLflow, and serves predictions through a REST API — containerized and CI-tested.

## Tech Stack
- **ML:** scikit-learn (Random Forest Classifier)
- **Experiment Tracking:** MLflow
- **Serving:** Flask REST API
- **Testing:** Pytest
- **Containerization:** Docker
- **CI/CD:** GitHub Actions

## What This Demonstrates
- Training a model with logged parameters and metrics (MLflow) instead of an
  untracked, one-off script — this is the core idea behind MLOps.
- Serving a trained model behind a REST API rather than only running it in a notebook.
- Automated testing of both the training pipeline and the serving API.
- A CI pipeline that retrains and re-validates the model on every push.

## Project Structure
```
├── train.py              # Trains the model, logs experiment to MLflow
├── app.py                 # Serves the trained model via a REST API
├── model/                 # Saved model artifact (generated by train.py)
├── tests/test_pipeline.py # Tests for training + serving
├── Dockerfile
└── .github/workflows/ci.yml
```

## Running Locally
```bash
pip install -r requirements.txt

# 1. Train the model (also logs to MLflow)
python train.py

# 2. View the MLflow experiment dashboard
mlflow ui
# open http://localhost:5000 in your browser

# 3. Serve the model
python app.py
# API now running at http://localhost:5001
```

## Making a Prediction
```bash
curl -X POST http://localhost:5001/predict \
  -H "Content-Type: application/json" \
  -d '{"features": [5.1, 3.5, 1.4, 0.2]}'

# Response:
# {"prediction": "setosa", "confidence": 1.0}
```

## Running Tests
```bash
pytest tests/ -v
```

## Running with Docker
```bash
docker build -t mlops-iris-pipeline .
docker run -p 5001:5001 mlops-iris-pipeline
curl http://localhost:5001/health
```

## CI/CD Pipeline
On every push to `main`, GitHub Actions:
1. Installs dependencies
2. Retrains the model and runs the full test suite
3. Builds the Docker image (only if tests pass)
